# Fixed C10 evidence resources

These resources retain the independently reviewed finite corpus. They do not
promote C10, C11, a product ABI, or an editor/runtime adapter. Historical draft
status strings inside the immutable author documents remain historical text;
the review/adoption record is separate.

`fixtures/c10/source-pins.json` identifies two unchanged dictionary-packed
bundles and seven later manifest/control/supplement documents. Decoding preserves
all parsed JSON values and property order, including the separate counterfactual
namespace. Each decoded document is checked by its compact JSON hash. The
original pretty-file byte hash is preserved as author provenance: decoding does
not reconstruct or claim to reproduce that file's whitespace bytes.

The four fixed-family generators reuse the original literal normalization.
They only copy bits, expand fixed references/repetitions, and bind explicit
case/phase fields. They do not run a primitive, evaluate a graph, derive an
expected numeric result, or read a candidate result. An unhandled expected
field fails generation. The generated case table is byte-identical to the
reviewed 9,061,599-byte table. Controls, case scopes, and explicit projection
presence also retain their original Rust-byte hashes.

Run the data checks from the repository root:

```sh
node --test scripts/lib/evaluation-lowering-c10-corpus.node-test.mjs
```

For compilation, create an empty temporary output directory and run:

```sh
node packages/runtime-native/crates/vivi-runtime-native-evaluation-lowering/tests/c10/generate.mjs --output-dir <empty-temporary-directory>
```

Generation verifies every output before writing with exclusive creation. It
does not delete files. The generated 9 MB Rust and approximately 21 MB field
ledger belong only in this owned temporary directory, not in Git. Native and
test-WASM must compile the same verified generated bytes.

The selected input JSON is regenerated byte-identically from the packed input
documents, with every declared numeric leaf bit checked. Input-only DFS identity
literals are regenerated from those same payloads. The one pinned
`fixtures/c10/frozen-c9-setups.rs` resource contains actual prior C9 setup, not
computed C10 expectations. It is not evidence that C9 executes on WASM.

`support/native.rs.in` and `support/wasm.rs.in` are the adopted-linkage templates:
the host renderer substitutes only `@REPO@`, `@SUPPORT@`, `@FIXTURES@` and
`@GENERATED@` with validated paths. Common support uses `C10_GENERATED_DIR` for
generated includes. These templates import the actual math rlib instead of
duplicating its source. They require the separately reviewed math visibility
and linkage change; this data slice does not make that production edit.

The dispatch rejects six native-only prerequisite indices with a trap. Normal
WASM execution excludes them; negative controls use a separate fresh instance
for each forbidden call and never reuse a trapped instance. The separate-case
marker applies only to the four WASM-applicable helper/raw/reuse descriptors.
Comparison failure records fixed diagnostic words and traps. Capacity controls
have no fallback panic, and initial immutable tables compare against the frozen
injected C9 input baseline. Negative controls corrupt only copied expectation or
actual-snapshot words, never a numerical fixture or the actual candidate.

The fixed manifest has 147 dispatch descriptors / 290 steps: 137 compound
cases, one actual helper case, two raw-control descriptors, one F43 descriptor
reusing eight compound cases, and six native prerequisite cases. F43 is not a
zero-step passing compound case. The six native C9 prerequisites are not WASM
numerical evidence. Six exact topology-generation selectors remain deferred
to C11. Absence of a projection field is distinct from a declared empty trace.

This data-only command does not itself prove arithmetic, allocation closure,
source-to-DAG bindings, or runnable native/WASM CI. Those require the shared
actual-source runner, its negative/allocator/capacity controls, and the exact
reviewed source/lock/compiler/ABI gates. Do not replace those gates with file
inventories or a green generation result.

## Current execution gate

`npm run check:runtime-native-evaluation-lowering` now runs the shared actual-source
runner with the ordinary Cargo-built math rlib: eight native tests in each of
debug and release, 137 test-WASM compound cases, the actual helper, 574 raw rows,
eight explicit compound-case reuses, ten fresh-instance dispatch/capacity traps,
and ordinary-production negative compilation checks. Comparison-negative and
allocation controls are separate from those ten traps. The gate also verifies
the pinned source-to-DAG mapping and bounded callable/allocation review records;
their historical status fields are not current implementation approval.

This is C10 evidence only, not C11 or activation. Generated files and local
execution evidence remain under the ignored checkout-local `tmp/` directory for
inspection. The runner does not clean them up or upload them.
